Release cockpit · theo Release Runbook

Mỗi thẻ là một việc phải quyết hoặc phải làm để sang phase sau: ai làm, ghi kết quả vào đâu, và bằng chứng nằm ở phần nào bên dưới. Click một phase để xem việc của phase đó.

    Bằng chứng

    Các phần dưới đây trả lời cho từng thẻ ở cockpit. Mỗi nút "Bằng chứng ↓" trong cockpit nhảy tới đúng phần.

    Bằng chứng A · Scope

    Những gì release này cam kết

    Mỗi hàng là một mục trong ROADMAP.md. Cột "Bước" cho biết mục đó chạm vào đâu trên đường đi request, và ai bị ảnh hưởng nếu nó hỏng. Cột "MP CI ở PR" cho biết PR đã chạy MP E2E trước khi merge chưa. Dev không chạy MP E2E, nên bằng chứng đầy đủ phải đến từ build trên commit rc.

    Bằng chứng B · Critical path

    Thay đổi nằm ở đâu trên luồng, và nếu có bug thì trace thế nào

    Mỗi journey là một chuỗi bước (theo Feature Matrix xlsx). Theo thay đổi: chọn một mục scope; node bị đổi được tô màu, đó là critical stage cần test. Trace bug: chọn triệu chứng; trang chỉ ra node, feature, PR nghi ngờ trong rc, và test CPU / GPU để reproduce rồi xác nhận. Click một node để xem riêng node đó.

    Mô hình lấy từ knowledge/inputs/LMCache_CPU_GPU_Feature_Matrix.xlsx. Bảng nối node → F và nhóm code → F đang là bản nháp chờ duyệt. Gate trong xlsx là đề xuất, không phải kết quả test.
    Bằng chứng C · Test theo feature

    PR chạm feature nào, và feature đó kéo theo những gì

    Mỗi hàng là một nhóm feature, dùng cùng mã với Feature matrix ở view Exploration. Trong cột PR: ● là đổi code chính của nhóm, ○ là đổi code phụ, △ là chỉ đổi test. Ba cột bên phải cho biết khi nhóm này đổi thì phải chạy lại gì: unit test bảo vệ, tier phải qua, workload E2E. Chọn một mục scope để chỉ xem những feature mà mục đó chạm. Click một hàng để lọc danh sách PR đi kèm ở Bằng chứng D.

    Định nghĩa: ký hiệu, bước trên đường đi request, tier test
    Bằng chứng D · Điểm cắt rc

    Chọn commit để cắt rc: những gì thực sự ship

    Mỗi vạch là một PR trên dev sau tag stable, cũ ở bên trái. Cắt rc tại một vạch thì mọi PR ở bên trái vạch đó đều ship; PR bên phải chỉ vào được bằng cherry-pick. Click vào một vạch để thử điểm cắt khác.

    Trong scopeBreaking, ngoài scopeNgoài scope, đổi code trên hot pathNgoài scope, khácVạch mờ = sau điểm cắt

    Ngoài scope nhưng vẫn ship. Mỗi PR cần một quyết định: thêm vào scope và release note, coi là nội bộ, hoặc revert trước khi cắt.

    Sau điểm cắt, chỉ vào rc bằng cherry-pick. Chỉ liệt kê PR đáng cân nhắc: bugfix trên hot path và breaking.
