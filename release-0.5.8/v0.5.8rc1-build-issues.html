v0.5.8rc1 image build: vLLM vs SGLang

One torch pin (2.14.0) feeds two engines. vLLM matches it. SGLang does not: 2 issues, 2 solutions.

Data: release run 43357734309 (2026-11-13) · SGLang pyproject.toml per tag · branch fix/sglang-torch-minor-match (7ae3da34)

Bối cảnh

LMCache ghim torch==2.14.0 trong pyproject.toml. Wheel trên PyPI được build với đúng torch này, nên phần code C++/CUDA của LMCache chỉ chắc chắn chạy được với torch 2.14.0.

Image lmcache/sglang = image chính thức lmsysorg/sglang + wheel LMCache cài thêm. Vì vậy CI phải chọn một bản SGLang dùng cùng torch với LMCache.

ISSUE 1 Không có bản SGLang nào dùng đúng torch 2.14.0

Bước "Resolve the newest SGLang release image" đi lùi từ bản SGLang mới nhất và tìm bản có torch giống hệt 2.14.0:

SGLangtorchKhớp 2.14.0?
v0.5.23, v0.5.222.14.1không (lệch bản vá)
v0.5.21 → v0.5.182.13.0không

Không tìm được bản nào khớp, nên bước này báo lỗi. Các bước build image phía sau bị skip, và không có image lmcache/sglang:v0.5.8rc1.

Lane vLLM thì OK: vLLM 0.33.0 dùng đúng torch 2.14.0, nên lmcache/vllm-openai:v0.5.8rc1 có trên Docker Hub.

ISSUE 2 Không thể đơn giản nâng lên 2.14.1

Cách sửa "dễ" là đổi pin của LMCache sang torch==2.14.1 cho khớp SGLang. Nhưng:

  • Cùng một pin này được dùng cho cả wheel PyPI, image vLLM và image SGLang.
  • vLLM 0.33.0 bắt buộc torch==2.14.0.
  • Nâng lên 2.14.1 thì SGLang khớp nhưng image vLLM lại hỏng.

Tóm lại: một pin torch phải phục vụ 2 engine đang dùng 2 bản vá khác nhau. Không có giá trị nào khớp cả hai.

SOLUTION 1 Chấp nhận cùng major.minor (2.14.x)

Branch fix/sglang-torch-minor-match (commit 7ae3da34):

  • Ưu tiên bản SGLang khớp đúng 2.14.0. Nếu không có, lấy bản mới nhất cùng 2.14.*, tức là v0.5.23 (torch 2.14.1).
  • Dockerfile vẫn kiểm tra kỹ: cài LMCache không được làm đổi torch, code native của LMCache phải load được, connector SGLang phải import được. Nếu 2.14.0 và 2.14.1 không tương thích thì build vẫn báo lỗi, không ship image hỏng.

Bản vá (2.14.0 → 2.14.1) thường giữ tương thích, nhưng không được đảm bảo. Các bước kiểm tra trên là lưới an toàn.

Trạng thái: mới push lên fork, chưa có PR, chưa chạy CI.

SOLUTION 2 Build LMCache ngay trên torch của SGLang

Không cài wheel từ PyPI nữa, mà build LMCache từ source bên trong image SGLang, với torch của chính SGLang (2.14.1).

  • Ưu: torch luôn khớp tuyệt đối, không phụ thuộc pin nào nữa.
  • Nhược: build lâu hơn, image cần thêm compiler CUDA, và wheel trong image khác wheel trên PyPI.

Trạng thái: đề xuất, chưa làm.

Tóm tắt

Solution 1 nhỏ, sửa được ngay cho 0.5.8.
Solution 2 bền hơn nhưng tốn công, nên cân nhắc cho bản sau.

MUSA wheel build: v0.5.7.post1 vs v0.5.8rc1

Same CI image, same broken torch_musa path. post1 never needs it. rc1 does (#5865): 2 issues, 2 solutions.

Data: release run 43357734309 job 131689267354 (2026-11-13) · dev publish runs 11-07..11-12 · branch fix/musa-wheel-build (6fe78159)

Bối cảnh

CI tải Docker image của Moore Threads (musa-pytorch-release-public:rc5.1.0…). Image này có sẵn torch 2.9.1 và torch_musa (phần mở rộng để torch chạy trên GPU MUSA). LMCache được build bên trong image này để tạo ra wheel lmcache-…+musa.

ISSUE 1 Python không tìm thấy torch_musa

Image có một lỗi ẩn từ trước:

  • Thư mục torch_musa nằm thật ở /home/torch_musa.
  • Nhưng Python được "đăng ký" để tìm nó ở một đường dẫn khác (đường dẫn trên máy Moore Threads lúc build image). Đường dẫn đó không tồn tại trong image.
  • Kết quả: import torch_musa báo ModuleNotFoundError.
Lúc build có gọi torch_musa?Kết quả
v0.5.7.post1Không (chỉ build C++ chung)wheel publish OK
v0.5.8rc1Có: #5865 thêm from torch_musa.utils import …build hỏng

Tóm lại: #5865 không viết sai. Nó chỉ là code đầu tiên cần torch_musa lúc build, nên làm lộ ra lỗi đã có sẵn trong image.

Thêm: bước kiểm tra đầu script chỉ import torch (vẫn OK, in ra "BUILD TORCH: 2.9.1"), nên lỗi chỉ hiện ra khoảng 8 phút sau, ở giữa setup.py.

ISSUE 2 Đỏ từ 11-07, 6 ngày sau mới biết

  1. 11-07 05:43 #5865 merge. PR chạy 0 check MUSA, nên không ai thấy lỗi.
  2. 11-07 05:44 Lần chạy publish đầu tiên trên dev sau khi merge: MUSA đã hỏng.
  3. 11-07 → 11-12 7 lần hỏng và 73 lần bị cancel, không có lần nào xanh. Không ai để ý.
  4. 11-13 Tag v0.5.8rc1, release hỏng. Lúc này mới phát hiện.

Vấn đề không nằm ở code, mà ở chỗ CI không báo lỗi đúng lúc: PR không kiểm tra MUSA, còn dev đỏ thì không ai nhìn.

SOLUTION 1 Chỉ cho Python chỗ tìm torch_musa

Sửa Issue 1. Branch fix/musa-wheel-build (commit 6fe78159):

  • Nếu import torch_musa hỏng mà /home/torch_musa có tồn tại, thì thêm /home/torch_musa vào PYTHONPATH.
  • Import torch_musa ngay đầu script (fail-fast): nếu vẫn hỏng thì báo lỗi sau vài giây, không phải chờ 8 phút.

Trạng thái: mới push lên fork, chưa có PR, chưa chạy CI.

SOLUTION 2 Bắt lỗi ngay ở PR

Sửa Issue 2. PR nào sửa file MUSA thì CI build wheel MUSA luôn:

  • setup_extensions/build_profiles/musa.py
  • csrc/musa/**

Nếu đã có check này, #5865 đã bị chặn ngay ngày 11-07, trước khi merge.

Trạng thái: đề xuất, chưa làm.
